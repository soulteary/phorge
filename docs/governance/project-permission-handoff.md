# Explicit project policy handoff

Status: isolated implementation; disabled by default. No deployment or permission migration.

The handoff changes an existing active ordinary leaf project's view and edit policies to one eligible native user. It is an explicit exception to the editor's normal self-lockout protection. It creates no owner or administrator role. Membership, join policy, Space and hierarchy are unchanged. Native parent visibility requirements, ancestor editing capabilities and member viewing rights remain authoritative. The preview reports whether the initiating administrator keeps view/edit access; this is not an exclusive-ownership guarantee.

Only a currently approved, enabled system administrator with native view and edit access may execute. An eligible distinct recipient must pass native final view/edit checks, including parent and Space visibility. Real native Web sessions or authenticated API/CLI tokens are rechecked under current database locks. Web confirmation additionally requires an actual POST and CSRF validation. Unknown custom-policy read sets, projects with descendants, milestones or milestone ancestors, archived projects, unsupported database topology and concurrent project-approval mode remain blocked.

Preview lasts five minutes and binds actor, actual credential, complete locked project/ancestor rows, membership sources, current account rows, Space rows, recipient, operation and final state. Its digest is freshness evidence, not authorization. Confirmation is explicit and typed. A changed source requires a new preview.

Commit is one native Project editor transaction containing a sealed modular transaction. The policy pair and native audit row commit or roll back together. Generic editors cannot request the exceptional operation. Post-commit Herald rule execution is excluded only for this sealed handoff, preventing an unpreviewed automated second policy edit. Ordinary native publication remains in place. An exact prior operation returns its durable receipt after current actor/credential checks; changed intent cannot reuse the operation. Unknown outcomes are not automatically retried. Handoff history is bounded at 1,000 operations per project; exceeding the bound blocks further handoffs rather than losing replay checks.

First delivery does not include project creation, custom policy-rule source expansion, member replacement, descendant-wide handoff, recipient acceptance workflow, or migration of native permission semantics. Those require separate reviewed source sets and product decisions. Existing administrator-approval policy is retained by requiring the executing current system administrator; ordinary editors cannot use this endpoint.

Endpoints: GET/POST /project/handoff/<id>/ and Conduit project.handoff (preview/commit). These are default-OFF and add no gateway authentication exemptions.

Merge gates: PHP 8.5.13 syntax and unit tests; real restored-schema SQL checks; Web and Conduit routing/CSRF/credential tests; stale-state and native rollback tests; repeat/mismatched operation tests; defaults-OFF behavior; exact current source admission; complete existing CI; independent security review.

Web confirmation uses the current locked native session for the native high-security check. Conduit uses an API/CLI token with no browser cookie; browser-authenticated Conduit, OAuth and cluster/device authentication are not supported for this operation. A receipt proves the policy/audit commit, not completion of downstream publication. If publication fails after commit, the response reports `postCommitProcessingComplete: false` and must not be treated as rollback.

Authorization reads and policy writes share the native transaction. A competing account revocation waits while the handoff holds its read set; a revocation which commits first invalidates the preview. This retains the native in-flight transaction boundary rather than promising instantaneous revocation. Local tests observe a real second-connection InnoDB lock wait. Explicit pre-COMMIT and post-COMMIT PHP Error controls distinguish rollback from durable commit. A writer whose rollback fails is disposed and refused for further handoff operations in that request.

Isolated regression command (no public ports or existing instance configuration): `python3 -B tests/governance/project_handoff/run.py --php-image <local-PHP-8.5.13-image> --gorge-file-binary <paired-file-executable>`. Add `--browser --playwright-module <local-package> --chromium <local-executable>` for the synthetic-session Web and real HTTP Conduit checks. Keep the output directory outside the checkout. The fixture checks source stability and removes its exact owned containers and synthetic schemas. Browser evidence is local acceptance; it does not establish deployment readiness.

Membership sources remain distinct: native automatic project visibility reads the materialized project membership edges; the Project Members object policy reads inverse user membership edges. Preview locks both those sources and the direct project edges, then applies their existing native meanings. It does not infer an aggregate rule from direct historical edges, repair the index, or grant membership. Direct and materialized sets are independently bounded at 1,000 entries per project/ancestor.
