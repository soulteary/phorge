# Governance batch 3: bounded native observations

This follows ADR v1.2 and the inactive foundations merged in #77 and #78.
The four native permission axes remain unchanged. No optional feature, route,
application, policy, writer, executor, schema patch or deployment is registered.
There is no production permission migration.

## Evidence boundaries

N05 distinguishes transaction shape classification, selected native expansion
methods, native automatic capabilities and effective native policy evaluation.
A successful local observation does not establish the closure of a complete
transaction editor. In particular, applying transactions in a rollback or a
preview is not a substitute for proving that an observation is read-only.
Herald, subscribers, application overrides and unsupported expansion paths
remain separate blockers.

N07 reads bounded real native table layouts in disposable application schemas.
The fixture creates synthetic rows using source-derived native definitions;
it does not use production records and does not rename synthetic version-epoch
tables to imply native coverage. The observation connection must have SELECT-only
privileges. Its own read-only consistent transaction covers the supported
schemas on a single physical server. Cross-server observations, a complete
native authorization dependency closure and a business-write transaction are
not certified by this read snapshot.

Source hashes are change observations, not grants or proof that a native
session remains valid. Unsupported policy rules, configuration overrides,
organization/appointment dependencies and incomplete source sets keep activation
blocked. Observation output never authorizes execution, even if its supported
sources match. Neither an account re-enable nor an unchanged target may be
interpreted as restoring a previously approved authorization.

## Integration gates

The existing N00 source-drift and membership-consumer inventories continue to
apply. New literal consumers require explicit review; no scanner exclusion or
reduced check substitutes for that review. Pure native methods and real-database
checks are reported separately. Database writes belong only to privileged setup,
concurrent synthetic fixture mutation and owned cleanup, never to the reader.

Required CI and final-head independent review must pass before a normal protected
merge. Main is checked again after merging. These development receipts do not
claim a release, deployment, production migration or completion of deferred
D08–D19. Unproved gates remain blocked.

## Reviewed fixture corrections

Cross-review corrected test-only prerequisites before accepting evidence:
configuration caches are initialized as normal native code expects and restored
in finally; pre-existing native SQL connections are rejected before fixture
cleanup ownership is established; synthetic project paths use the native
PHID-derived binary path/key format; parent projects use legal materialized
membership instead of fabricated direct-member edges. Native custom and named
policy checks execute real project queries. No native policy method is stubbed.

Session bindings carry SHA-256 digests of stored native session keys; three
role-specific row-level eligibility checks prevent a digest mismatch from being
hidden behind the globally blocked closure. This does not certify the entire
native session authentication protocol. Project path/key/depth participate in
native observations, while the hierarchy evaluator itself remains unsupported.

Strict deployment-selector rejection includes the string "0". Scope is checked
again on snapshot finish. Schema string types and SQL-side long-value guards
prevent unbounded values from being fetched first and checked only afterwards.
Elapsed budgets cover completion as well as the start of observations.

Capability observations additionally require an owned native SQL context. The
isolated opt-in alone is not authority to use an arbitrary in-memory environment.
A test-only context verifies exact default/dictionary configuration sources,
effective routing, the private namespace, actual SELECT-only grants and the
source marker before native queries. Unknown pre-existing connections are
refused rather than adopted or closed. Request-cache isolation and restoration
keep cached database routes from bypassing the verified context.

## Development validation

The final supported-runtime run passed 78 pure native methods (51 existing,
21 native-observation methods and six source-reader contract methods) and 85
real MySQL checks. The local source-copy receipt matched all 29 governance
PHP/SQL/map/runner files, including the owned capability context. Governance
Python has 31 tests and the membership/permission suite has 81. MySQL ran in an
owned network-none pod with tmpfs data and no published ports. The fixture
removed all eight owned schemas and its SELECT-only account.

The required native CI executes the new fixture and publishes a separate
`governance-batch-3-php-8.5.12` artifact. Hosted checks, final-head review and
post-merge main results must be recorded separately; these local counts alone
do not satisfy the protected merge gate. Counts describe methods/scenarios,
not complete native application or permission coverage.
