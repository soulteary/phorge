# Native administrator grant notification candidate

This independent successor adds one real producer: a native `PhabricatorUserTransactionEditor` grant from false to true. It does not enable notifications or deploy anything. The original validation, MFA and authorization remain native. Default-off operations retain the existing transaction behavior.

The native editor locks and reloads the target before generating old/new values. Before persistence, the native internal-effects callback verifies User and USER-transaction InnoDB engines and holds their metadata locks. Grant internal effects only set the in-memory role. It then persists the real USER transaction and calls final effects before committing the User writer. Only that final-effects lifetime opens a private editor context for this particular object and transaction; finally closes it, including on exceptions. A retained editor cannot append a past event later. The hook reads the actual persisted native transaction and current actor row on that writer. The original actor must still be an administrator and not disabled; an actor PHID cannot be inferred from email or supplied metadata. Omnipotent actors without this normal provenance remain unsupported in this candidate.

The event binds the native transaction PHID and target PHID through an operation digest, and the actual author through an actor digest. Names, addresses, transaction bodies and recipient lists are not copied into its metadata. Exact canonical false-to-true JSON values and the native transaction type are required. The qualified Meta event and relay inserts borrow the same User connection and physical transaction. A separate owned primary observer must see the committed User role, exact native transaction and event together. There is no cross-database early commit. The existing central notification worker and per-attempt mail policy provide current qualified administrator recipients and a generic sign-in link to `/people/`. Recipient qualification also runs the actual native People query for the bound subject; a missing or native-invisible subject cannot be used as a deliverable source. No invented Space policy is applied to User objects.

A focused real fixture is registered as `--notice-admin-grant`. It uses actual native sessions, CSRF and the User transaction editor, a real owned Gorge taskqueue, a real fenced lease and the native Conduit worker handler. It checks default-off behavior, real persisted grant/outbox, metadata privacy, source reload, native no-effect, ended-context refusal, queue replay, handler/mail preparation, worker replay, current recipient revocation, a real late relay SQL fault rolling back User/USER transaction/notice generation/event/relay, and a successful retry, and actual MyISAM source refusal before User or transaction persistence. Removing the administrator role while the notice event table is missing must still commit. The fixture does not handcraft mail or claim a Go daemon, HTTP gateway or SMTP run.

Removal and no-effect never consult notice configuration or storage in this hook. This preserves the existing emergency tightening path. It also means this candidate does not yet deliver administrator-removal notices. A durable removal producer must be designed without adding a new synchronous notice-storage dependency to role contraction. Raw role writers, remaining producer and recipient classes, committed restoration-success notifications, the external activation lifecycle and its OFF-to-ON replay boundary remain separate blocked obligations. This candidate does not claim all administrator changes, all notification producers, global source atomicity or activation readiness.

This source is based on the verified `8835c06` component. Its new producer has not been run on the supported native runtime or SQL yet. Existing component results are historical evidence only. Current-main policy and documentation integration will be reconciled explicitly before any PR update. Event metadata remains schema version 1; the existing account binding remains version 2. No legacy binding or immutable snapshot is rewritten.
