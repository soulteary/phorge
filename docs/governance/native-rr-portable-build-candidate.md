# Native RR portable build candidate

This independent successor prepares only a trusted hosted build chain. It does not alter the accepted ARM64/rootbench RR21 path or execute the helper, PHP, SQL or any service. The fixed workflow runs only for its exact Go/recipe/test paths on pull requests, or through explicit workflow dispatch. A pull-request build records the actual synthetic merge checkout SHA from GITHUB_SHA; it does not label that artifact as a PR-head measurement. No RR21 hosted acceptance follows from building an artifact.

The workflow obtains the exact current checkout with a read-only token and Go 1.27.3. It populates only the locked `golang.org/x/sys v0.49.0` module through the checksum database. The repository recipe then verifies the whole source is clean, its HEAD equals the same CI run's checkout SHA, all five Go source files and all three recipe/workflow files equal committed bytes, and the module cache verifies before and after compilation. Compilation is offline, CGO-free, Linux/AMD64, with no inherited Go overlays, workspace or experiment flags. Actual `go version -m -json` must prove the same revision, clean VCS, exact module dependency, architecture, toolchain and reviewed build settings. The output records actual binary bytes and toolchain digest; no caller-supplied binary hash is accepted as provenance.

The private build output is exclusive and outside the source tree. It includes the actual build-info bytes and a source-bound build record. A descriptor is explicitly not execution authority. The next slice must establish an external owned same-run anchor from the fixed runner, bind the descriptor's exact bytes and source/recipe hashes to that anchor, and make the isolated PHP consumer validate it independently. An arbitrary writable descriptor, caller environment hash or unknown profile must not activate a portable path. Rootbench's exact `b465…` binary and fixed paths remain unchanged.

After that consumer and runner are independently reviewed, a separate RR21 job should use MySQL 8.4.13 with required Performance Schema instrumentation, a fresh owned source stage, the trusted native parser build, an exact cold mapper, all 277 native pure methods in 48 classes and the unchanged 21 SQL checks. The job must preserve CREATE-before external leases, pidfd ownership, independent SQL-session cleanup, fixed minimum grants, unknown-state retention, real CLI/in-process equality and whole-source hashing. MySQL 8.0 from the existing general Native job is not silently substituted for that profile. Minimum-grant negatives, transport failures and TERM/KILL fault coverage remain separate unproved gates.

Host controls exercise provenance mutation rejection, actual exclusive filesystem artifacts, signed-source byte checks and same-run identity. They do not constitute a Linux AMD64 build, a trusted external anchor, a daemon run, a native SQL result, or hosted RR21 acceptance.


The build-only stage above remains historical scope. The independent [owned hosted RR21 candidate](native-rr-portable-anchor-candidate.md) adds the external anchor, PHP consumer and full isolated runner; it still requires actual CI execution and artifact acceptance.
