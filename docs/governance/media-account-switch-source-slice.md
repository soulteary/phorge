# Native media account switch source slice

This test-only addition is unbound and has no deployment, public hostname,
certificate, browser-launch, SQL or process authority. Production source and
optional feature defaults are unchanged. It extends only the owned remote media
fixture; the localhost fixture's prior executable statements remain identical
when the exact additions are removed by the hash-constrained inverse test.

The remote fixture persists a second real native nonadmin account, primary
verified email and real password through the native password engine. It checks
zero preseeded sessions and uses the existing password provider. The remote author is also explicitly nonadmin; localhost retains its original
admin author. The ordinary account is not the author of the original NOONE file; it owns a separate NOONE
Gorge file so that fresh media credential functionality can be proved positive.
Its version2 `account_switch` object (including actual native author-admin false) is private ready data only. Credentials,
PHIDs, URLs and cookie values must not appear in public receipts.

`tests/governance/media_browser_account_switch.py` composes with the independently
captured existing normal-TLS baseline flow module. The Root parent must pin both
modules and the approved origin profile, provide a fresh normally verified TLS
BrowserContext, and keep its actual native fixture alive through all steps. It
must supply the current signed fixture source, not an old ready file.

`media_browser_account_switch_v3.execute_bound_guest()` is the fixed installed
remote guest entry. It uses the actual reviewed normal-TLS provider context and
baseline flow, calls the six-obligation slice and feeds both results into the
current strict consumer. `consume()` sends an unchanged old-shape envelope to
the import-relocated old ten-check validator, then checks the separate exact six
obligations and emits a whitelist-only public projection. The original external
v2 consumer and ten-check set are unchanged; function-body inverse provenance
and negative controls protect this boundary. A fixture digest, source revision
and exact module digests are bound by independently captured Root review bytes;
null authority refuses before input/module/context operations.

The physical installer/host executor still needs its separately reviewed v3
package binding: old nine guest source files plus exactly four new runtime files
(slice, v3 entry, legacy consumer, legacy obligations), thirteen total. The old
nine-file installer must refuse this new package rather than silently broaden.
The new fixed guest command invokes `execute_bound_guest`, not the old
`normal_tls_provider.execute_guest` ten-only dispatcher. This source slice adds
the concrete guest entry/consumer; it does not claim that installer, remote
process, TLS endpoint, native session or browser has executed.

The exact protocol is:

1. Run the original ten-check native author login, one-time exchange and native
   logout flow in the same empty context. Capture the author's native session
   binding privately from its real application authorize request.
2. Keep the original media cookie values. Use the real password form to log the
   ordinary account into that same context; require the actual native form POST and
   a changed host-only native session. The username convenience cookie is not
   identity evidence.
3. Perform a real file-origin fetch. Require the outgoing original media cookie
   values and an HTTP403 without the author's private content.
4. Use the original native authorize/iframe/postMessage issue/redeem sequence for
   the ordinary user's own file. Require actual HTTP200, exact content SHA and
   no-store, plus the existing strict media-cookie scope validation.
5. With these working new media credentials, fetch the original author's file.
   Require their exact values on the real request and HTTP403 without private
   bytes. This is a policy isolation check, not merely an expired-cookie check.

The parent closes the BrowserContext and performs its separately reviewed
relay/tunnel/socket/native HTTP/Image/SQL-zero/keeper cleanup. No cookie setter,
preseeded session, synthetic HTTP identity or application JavaScript replacement
is exposed. Host tests use explicit browser and baseline-flow collaborators;
they exercise actual slice sequencing, request observation, failure handling and
real native unsaved User objects. Persistence, TLS, HTTP, actual browser execution
and parent cleanup remain runtime gates. This slice does not prove N12 latency,
account disable/re-enable, OTP, all media payload cases, or all N09/N10 completion.
