## Selected behavior observed

The owned fixture created a real native organization operation and its pending
notice. The existing relay and workers prepared and submitted it through the
actual mail path to an isolated SMTP capture. The captured MIME contained a
generic notification and a protected history link; private notice content was
not placed in the message. No external recipient or real person's data was
used.

A real browser used the native password provider and its native CSRF form,
without injected browser sessions. The selected recipient signed in and opened
the protected history page with HTTP 200 and the expected synthetic operation
row. A separate ordinary user received HTTP 403 without the protected row or
private content. After native logout, the anonymous history request returned
HTTP 200 containing the structurally verified native login form, no history
rows, and no private content. This native login response is not treated as
anonymous access to history.

The parent observed native cookie/session identity and ordered login, history,
logout and denial frames. Its metadata observer used a short-lived,
default-deny native write guard: only the native session engine's own scoped
TTL refresh was allowed. It did not disable CSRF or globally allow writes.

Retrying the same selected event retained one mail mapping and one SMTP
capture. This proves the observed same-event replay/fanout behavior. It does
not simulate a lost SMTP DATA acknowledgement or prove exactly-once visible
delivery.

The native receipt satisfied all 19 source-derived success checks and reported
55 owned schemas and four owned runtime users removed, with its separately

parent cleanup checks passed. The final full SOURCE check covered the same
8,979 entries and 36 aliases. These are owned-fixture cleanup facts, not an
online migration or a claim to delete arbitrary resources.
