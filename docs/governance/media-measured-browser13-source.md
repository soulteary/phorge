# Measured native source and thirteen-file normal TLS browser package

This is an unbound test-only successor. It changes no production source or
optional-feature defaults, creates no public hostname or route and performs no
VM or service action. The original nine-file installer is unchanged. The source
includes a deterministic thirteen-file artifact producer, a separate installer,
a read-only native source receiver, a host collector, a concrete host executor
and a compatible remote-stage method. They are executable source, not a claimed
actual deployment.

The nine original guest source inputs are copied exactly under
`tests/governance/media_browser_runtime_base/`; their commit, tree and SHA256
provenance is recorded separately. The four added runtime inputs are the account
switch slice, measured versioned entry/consumer, old ten-check compatibility
consumer and its exact obligations. The private artifact producer emits only
those thirteen names. The old nine-file installer must continue rejecting this
bundle. Root later binds metadata in an independent captured artifact set;
original source snapshots must not be overwritten.

`media_browser_install13` checks the externally pinned bundle SHA before creating
anything, requires canonical base64 and exactly thirteen files, retains held
parent/child/file FDs through stable write/readback and final entry verification,
and refuses replacement, special modes, hardlinks, zero writes and unknown
existing directories. It never deletes or retries unknown state. Data remains
0600 in its new nonce directory. `execute_bound()` rejects null authority before
reading stdin. The actual browser image must independently contain the exact
installer at the fixed root-owned0444 single-link path
`/opt/phorge-media-browser/source_install13.py`; this package does not install it
into any image. Host bootstrap captures/hash-verifies that file with NONBLOCK and
NOFOLLOW before compiling the captured bytes.

Before browser creation or installation, the new host executor calls the real
native collector. It reads the current owned `router.json` through the existing
native ownership RPC, compares owner, exact origins and transport proof digest,
and inspects the actual owned forward server socket and live thread. It then
sends the independently captured 1ce verifier plus a fixed read-only receiver to
the native PHP container. The receiver verifies every signed file/alias and root
identity, then computes the fixture digest twice through one held regular FD,
with full stamp/path/parent checks. The fixed production root is
`/tmp/governance-src`; input cannot select another root or fixture path. Main
requires PHP8.5.12/Linux/UID0 and a captured request digest before stdin use.
There is no SQL, file modification, executable invocation or service action in
this receiver. The r+b streams are solely the reviewed FIFO-safe no-write read
pattern.

Revision/tree are not guessed from guest files or reported as a guest Git
measurement. They are bound to Root's independently reviewed signed whole-source
manifest. Actual file verification, manifest/alias digest, current root identity
and measured fixture SHA must all agree with that manifest and the current
native tuple. The host derives the tuple's origins/proof from the actual owned
router and its port from the current listener. Missing or mismatching measurement
fails before engine creation/installation; the guest repeats strict validation
before importing browser dependencies. A caller-supplied `passed` label or old
ready JSON cannot replace this collector call.

The fixed host executor uses the existing independently captured strict engine
and owned-container lifecycle, with NEW null-default execution, engine, runtime,
bundle and installer pins. It creates the browser only after native measurement,
installs the thirteen-source data bundle, invokes
`media_browser_account_switch_v3.execute_bound_guest`, validates the public
receipt and attempts known-container cleanup while preserving a primary error.
`MeasuredRemoteStage.execute(packet, local_proof, adapter)` is the compatible
remote-lifecycle boundary. The captured outer must select this versioned stage;
it must not call the old ten-only dispatcher. Root still needs to assemble and
peer that final captured launcher/remote asset installation packet.

The normal TLS provider's actual binary, dependency, normal trust and controlled
negative-endpoint checks remain unchanged. Current unbound artifact source
contains null runtime/origin/review roles and cannot prove or run the browser
flow. Root must create a new bound artifact set, verify each allowed constant
binding against its unbound source, update provider/switch/fixture source pins,
then recompute the thirteen-file bundle SHA. No historical authority is copied.
Native fixture and browser resources, normal DNS/egress in the actual browser
namespace, fresh root/source/assets/PROCESS observer and independent cleanup all
remain actual runtime gates. The old PHP namespace's earlier failed DNS lookup
is not proof of browser reachability. No hosts-file, CA, TLS-warning bypass or
network widening is authorized here.

Host tests run the real installer on owned temporary filesystem objects and the
real fullSOURCE/fixture-hash PHP functions. Only the guest root/platform dispatch,
native SQL/router transport, server listener and engine/browser transports are
explicit collaborators in those controls. They do not claim actual native SQL,
TLS, browser, Linux sandbox or remote lifecycle acceptance. Public projection is
fixed counts/check labels/source hashes; router secrets, credentials, origins and
cookie values remain private. New positive public hosts and any controlled
negative endpoint routing require separate explicit approval after the fully
resolved gateway/private-backend/rollback configuration is reviewed.
