# Source-bound hosted RR21 candidate

This independent successor adds an owned external anchor, PHP consumer and complete fixed hosted RR21 runner. It preserves the accepted ARM64 Rootbench binary SHA and paths when no CI profile is selected. It does not install a production capability, enable recovery, or claim that this new hosted profile has passed.

The workflow uses PHP 8.5.12 and an owned MySQL 8.4.13 service, published only on 127.0.0.1. The runner independently inspects the actual GitHub service container, image ID, private network, nonprivileged isolation and loopback port binding, then verifies the actual database version, bootstrap principal and empty role/proxy state. It never accepts a caller descriptor, binary digest, service command or external database endpoint.

The fixed workflow/job identity is `soulteary/phorge/.github/workflows/native-rr-owner-build.yml` / `owner-build`. Every measurement binds the actual same-run checkout SHA. Pull-request synthetic merge commits are explicitly distinguished from dispatch checkouts; neither is relabeled as a PR-head measurement.

Before source staging, helper installation or anchor creation, the runner persists an exclusive private external ownership lease. A separate seed, written before the actual build, binds five owner-helper sources and ten recipe/workflow/consumer/gate files. The fixed recipe verifies the module directory contains exactly the five reviewed regular files, with no additional file, directory or parent-chain symlink. The workflow triggers on the whole module prefix so a new input cannot bypass that refusal. Both prebuild and postbuild source checks enforce this inventory.

The actual same-source Linux AMD64 build runs offline with Go 1.27.3 and the locked, independently verified module cache. The runner rereads the real binary's Go build information and actual Go toolchain bytes; it compares the build record with its separately held seed, current source and actual bytes. Only then does it create the immutable anchor. The expected anchor digest, directory inode and run fields remain separate parent control values. They are never recovered from a descriptor or accepted as a caller-supplied replacement for build provenance.

The PHP consumer requires that fixed workflow/job/run, explicit isolated profile, private directory inode/owner/mode, canonical immutable seed/anchor, all fifteen current source bindings, actual binary/PHP/parser bytes and fixed paths. Missing control, unknown profile, changed source, wrong run, executable alias or unknown ownership fails closed. Getters revalidate the anchor. Its data validation explicitly grants no production authority. The ordinary Rootbench branch retains its exact `b465…` binary and PHP paths.

The runner creates a fresh, exclusive `/tmp/governance-src` from the current Git archive. It refuses inherited caches and existing source/binary directories. A bounded data-only extractor rejects devices, hardlinks, sparse entries, traversal and parent aliases; source symlinks must point directly to a regular internal archive member. The native parser is built inside this owned stage, and a cold native mapper must reproduce the signed classmap before any pure or SQL checks.

The actual hosted run then executes all 274 native pure methods / 47 classes and the unchanged 21 focused checks (six bootstrap, twelve two-case SQL obligations and three cleanup checks). External metadata ownership is persisted before CREATE. SQL uses the real fixed native fixture and separately owned same-primary observer. A full PHP/SQL/public-suffix manifest, including exact signed alias targets, is checked. The actual strict Python CLI must have empty stderr and equal in-process acceptance. Only a successful native outcome, whole-source match, strict acceptance and complete owned cleanup can produce a hosted checkpoint.

The source, binary and anchor are removed only with retained identity evidence. Malformed native output, source drift or unknown SQL-session cleanup retains those objects for reconciliation. No bare PID/SQL-thread kill or DROP USER substitute is introduced; existing pidfd ownership and independent SQL-session cleanup stay intact. Public artifacts contain provenance, safe receipts, role digests and status fields, never external controls, raw owner nonces, private leases or stage paths. A failed or build-only record is not a hosted RR21 success.

This source candidate has not been built or run on the new hosted profile. Host controls cover actual private files and PHP data validation, source/provenance mutations, fixed-command runner orchestration and success-checkpoint rejection on failures. They do not prove a real MySQL execution. Minimum-grant SQL negatives, transport-loss and TERM/KILL fault matrices, role/proxy/dynamic grant closure, all recovery families and a production companion remain unproved. Actual CI execution and independent artifact review remain required; no VM, deployment or production activation is performed here.
