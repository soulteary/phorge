## Validation

Focused PHP unit regressions and the disposable MySQL contract are wired into
`.github/workflows/gorge-runtime-contracts.yml`. The unit job runs on PHP 8.3,
8.4 and 8.5; this records the intended CI matrix, not a local pass for all three.

```sh
php scripts/runtime/build.php all
php bin/rebuild-library-map
php bin/celerity map
php bin/unit --no-coverage \
  src/infrastructure/markup/__tests__/PhutilRemarkupEngineTestCase.php \
  src/applications/search/engine/__tests__/PhabricatorApplicationSearchEngineTestCase.php \
  src/applications/phid/query/__tests__/PhabricatorHandleQueryTestCase.php \
  src/applications/ponder/view/__tests__/PonderAddAnswerViewTestCase.php \
  src/infrastructure/internationalization/scope/__tests__/PhabricatorLocaleScopeGuardTestCase.php
GORGE_TEST_MYSQL_PORT=3306 GORGE_TEST_MYSQL_PASSWORD=disposable-only \
  php tests/contract/upstream/cache.php
php scripts/runtime/verify.php
bash .github/scripts/check-retired-app-references.sh
```

The MySQL contract creates and drops random databases. It checks empty global
preferences are cached without repeat writes, preference changes are visible
after invalidation, and notification count caches are invalidated only when
unread rows change, both in storage and on the user object. It does not claim
production performance measurements or multi-node integration coverage.

Local verification used PHP 8.5.8 and a disposable MySQL 8.0 container:
17 focused PHP/Conduit tests, 33 translation-maintenance tests, the MySQL
cache contract, native i18n extraction
and validation, runtime integrity/compatibility, transport contracts, and the
retired-symbol reference check passed. Restoring either old cache implementation
makes the new MySQL regression fail, confirming it detects the original defects.
No full paired Gorge acceptance or authenticated browser workflow is claimed.
