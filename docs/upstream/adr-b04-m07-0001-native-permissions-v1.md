# ADR-B04-M07-0001: Versioned project permissions

Document version: 1.0.0
Status: **Proposed recommendation; not accepted or activated**
Date: 2026-11-01
Evidence baseline: `0c02bb92a491d86c4492b815698cd89fe9cd1438` / [PR #64](https://github.com/soulteary/phorge/pull/64)

## Decision boundary

建议保持 **native-v1**。本文件制定四个独立权限轴的决策，不更改运行代码、开关、物化索引、成员边或线上权限。`native-v1` 是既有审计基线标识；不新增运行时模型选择器。签署角色和四轴处置仍待确认。

## Evidence and limitations

已验证的恢复样本包含13项目、6普通子项、2里程碑和13比较主体；其中12项目和9个请求账号为合成数据。10类请求主体（含匿名）在两个阶段完成六路由1440个逻辑单元及519项附加检查；41项权限单元、27项恢复集成与PR/main必需CI通过。

每候选每阶段845个底层策略/成员比较单元，五候选共十次比较。原生HTTP证据不等于候选路由已实现；候选计数不是实际可提交编辑数。私有兄弟可能在底层继承CAN_EDIT，但缺少CAN_VIEW时原生编辑路由仍拒绝。无未知项仅适用于本受控数据域，不能外推Space、自定义策略或所有任务卡片组合。

复核来源：[审计发现](b04-m07-audit-findings-2026-11-01.md)、[原生路由协议](b04-m07-native-route-acceptance.md)、[只读审计器](b04-m07-readonly-auditor.md)。完整脱敏设计数据见同目录 [结构化ADR与矩阵](adr-b04-m07-0001-native-permissions-v1.json)，及工作区导出 `b04-m07-permission-model-adr-v1.0.0.json`。

## Four independent decisions

### V: 子项目可见性

**推荐：** 保留原生祖先可见性约束与成员自动授权；不启用普通子项目独立可见性。

**约束：** 以当前原生 ProjectQuery / PolicyFilter 为准，保留成员自动授权和祖先过滤的组合语义。users 等存储策略本身不能证明最终可见。审批/停用、应用和 Space 边界仍须独立满足；不以管理员、创建者身份替代真实查看判定。里程碑继续继承父项目，不成为独立公开边界。

**证据：** independent-view-v1 策略预览新增查看授权 29 / 31；原生路由已验证隐藏父项、可见祖父及后代成员场景。

**取舍：** 保住祖先隐私和当前协作预期；代价是无法直接公开隐藏父项下的普通子项。若业务需要独立公开，应另建明确公开边界或提出新模型，不用查询层旁路实现。

**备选：** 独立可见性仅作为 future-v2 研究选项；须逐对象审议潜在扩权、祖先名称/路径/数量泄露及所有消费者。

**待确认：** Q01, Q02。

### E: 编辑继承

**推荐：** 保留原生父项目编辑权继承；有效编辑必须同时具备当前查看权与编辑权。

**约束：** 不实施 M03 的取消继承行为。显式子编辑者继续有效，里程碑沿用父项目语义。仅继承底层 CAN_EDIT 而缺少 CAN_VIEW 时，编辑路由和写入仍拒绝；会话、索引或旧表单不能冻结撤权前的权限。API、事务、批量操作须在提交时复核。

**证据：** explicit-edit-v1 的编辑/加入策略各变化为拒绝 3 / 2；这些是底层策略单元，不是实际 HTTP 编辑损失数。原生矩阵验证父编辑者撤权、显式子编辑者保留及私有兄弟拒绝。

**取舍：** 延续父项目管理职责，避免现有编辑者突然失权；代价是父编辑职责覆盖较广，不满足严格子团队自治。通过显式组织边界或后续独立 ADR 解决，不直接取消全部继承。

**备选：** 显式编辑模型需先确定职责接替者和恢复路径，检查锁定成员加入/离开等连带能力；不得把历史创建者自动升为管理员。

**待确认：** Q03, Q04。

### M: 成员聚合

**推荐：** 运行期保留原生 type60 物化解释及里程碑继承；只读报告区分 type13 直接边、原生物化边和候选推导边。

**约束：** type13 与 type60 不是可互换的授权事实；不将“所有直接边 + 后代”计算结果写回当前授权索引。当前 obj.project.members、成员展示、自动可见性与 join/leave 消费者继续遵从原生行为。新来源/代际字段仅可先设计和离线验证，禁止双写、切换消费者或发布影子索引为权威。

**证据：** direct-members-v1 查看新增 2 / 2、拒绝 9 / 6，member-index 为 +1/-7、+1/-5；self-descendants-v1 查看新增 2 / 2、索引各新增1。

**取舍：** 保留后代成员到祖先的当前可达性，避免无来源的旧边被提权；代价是原生成员含义不如“直接成员”直观，来源展示和消费者梳理仍需补齐。

**备选：** 未来可设计 direct writable / derived read-only 两层结构，但结构拆分不等于授权模型改用 self-descendants。新语义、新 generation、消费者兼容和原子发布须分别评审。

**待确认：** Q05, Q06。

### H: 历史边处理

**推荐：** 保留来源未知的历史边并标记歧义；仅形成受限复核清单，不自动删除、补齐或提权。

**约束：** 缺少物化边、创建时间较早、成员位置或当前索引差异均不足以证明某条直接边应删除或应授予访问。后续只读清单应区分可靠事务证据、来源无法确认、悬空引用和账号准入状态；其中结构、来源与生命周期分列，不能相互排斥或据此修复。当前工具不能从边形状恢复历史来源。任一更正须另行授权，绑定原边指纹、理由、审核者、前后值及逆操作，先在恢复副本验证。

**证据：** 恢复/撤权阶段分别有6 / 5条直接边被审计器列为来源不明；只有1条刻意构造为旧边形状，不能称为发现6个线上历史缺陷。

**取舍：** 避免误删显式邀请、重建索引时意外扩权或自动恢复停用账号；代价是暂时保留数据歧义，不能靠自动“清理”马上统一语义。

**备选：** 仅在负责人确认且证据充分后提出独立 correction manifest；native 修复、语义迁移和账号生命周期操作应分开审批、执行与回退。

**待确认：** Q07, Q08。

## Version and acceptance rules

- 文档1.0.0是建议版，不代表模型已发布或负责人已接受。
- native-v1是既有审计基线标识；当前应用不新增版本选择器/开关。
- 澄清、引用、无语义修订可递增文档补丁并记录原因；接受后语义变更须新ADR/新模型ID并显式supersede。
- 独立四轴组合必须有完整不可变模型定义，不能任意拼接现有候选ID或将combined-v1直接视为发布版本。
- 未来代码/worker/索引generation须明确兼容；未知/混合版本的写入拒绝是待实现门禁，不是已验证能力。

接受记录：维护者和策略负责人尚未签署；项目负责人尚未逐对象处置差异。四轴均为 pending。接受“保留原生”也不等于授权未来迁移。若未来拒绝其中某轴，只能开启独立后继设计，不能隐式使其他轴同时生效。

## Runtime responsibility and invariants

- Phorge 持有账户准入、应用/Space/对象策略和动作/事务判定的权威；Gorge继续提供检索、文件、队列等现有服务。旧搜索结果、缓存或Feed不能代替当前策略复核。
- 将存储策略、直接边、物化成员、候选聚合、底层能力、最终路由和提交结果分别记录；看板项目可见不意味着私有任务卡片可见。
- 不新增 viewer/editor/admin 角色，不把历史创建者或管理员标记当作项目救援授权。角色与最后管理者恢复另做 ADR。
- 可选控制保持 flat / off / native / false；搜索 source-scan / projection-shadow 保持关闭。本次不启动生产采集、修复、更正、迁移或发布。

## Future migration gates (not authorized)

1. 四轴及支持域接受，发布模型定义与源码/schema兼容范围；所有潜在授权变化由负责人处置，未知不得当作安全通过。

3. 在独立恢复副本验证备份恢复、并发回放、崩溃续跑、重复操作和混合worker拒绝。
4. 回退覆盖切换后的新直接边、修改和撤权；恢复旧二进制不是数据回退。恢复目标及窗口尚待Q10确认。
5. 另行提出具体、可审阅的更正或发布方案并取得操作授权。本 ADR 及本次用户请求均不授权上线权限迁移。
