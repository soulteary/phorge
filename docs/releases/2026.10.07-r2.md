## 发布顺序

1. 合并 Gorge `2026.10.07-r2` 发布 PR，将新标签指向合并后的 `main`，发布 Release。
2. 等待 Gorge Release 镜像工作流全部成功；检查 `ghcr.io/soulteary/gorge` 的 `render`、`conduit`、`notification`、`file-storage`、`webhook`、`taskqueue`、`worker`、`db-api`、`mailer`、`search`、`gitea`、`image`、`maintenance`、`integrations` 服务标签均带 `-2026.10.07-r2`，且可以拉取。
3. 核对 Gorge 最终标签提交，更新 Phorge 的 `GORGE_CONTRACT_REF`，对该不可变提交重新运行配对契约检查。所有检查通过后再合并本 PR；本 PR 的默认值依赖第 2 步的镜像。
4. 在合并后的 Phorge `main` 上创建新标签 `2026.10.07-r2`，发布 Release，使用本版本说明并记录最终配对提交和验收产物。

默认 `docker-compose.yml` 的 Gitea profile 仍需显式设置 `GORGE_GITEA_IMAGE_TAG=2026.10.07-r2`。共用服务定义 `docker-compose.gorge.yml` 保留原有的公共标签继承方式，未单独指定时使用公共 `r2`，发布前同样要检查 Gitea 镜像。现有安装自己的 `.env` 不会自动变化：升级时检查公共标签及各服务覆盖标签，并先完成备份。

python3 deploy/acceptance/accept.py --gorge-dir /path/to/gorge --check
