# Selected native AuthSession INSERT lease candidate

This isolated, default-off protocol adds `PhorgeRecoverySessionProducerFence::beginLease(observer, subject)` without adopting another caller's transaction. It uses the actual native User writer at READ COMMITTED and an independent native metadata observer. It is separate from Task/File owned RR scopes and restoration v3 composition.

The exact User PRIMARY record is locked FOR UPDATE before a bounded current capture of the subject's native Session rows. The unchanged supported AuthSession INSERT producer takes a conflicting PRIMARY SHARE before the actual INSERT. Empty sets therefore have a selected producer fence. Capture and recapture bind the selected subject, current Session set and fixed observed grant syntax. Physical writer/observer identities, profile, native depth and the exact performance-schema transaction event must remain stable. A changed source or failed observation poisons this lease. Commit and rollback require independent observation of the exact terminal transaction event. Lost commit ACK remains a failed operation even if independent committed evidence later permits releasing the reservation. Unknown state stays quarantined; no reconnect or rollback inference creates evidence.

The lease reserves its writer against reentrant use by this selected native producer only. It is not a universal quarantine of every native DAO, nor a grant, DDL, raw-SQL, role, proxy, dynamic-grant, all-session-producer or ABA lease. The writer profile now decodes the actual fixture global USAGE plus escaped schema-scoped CRUD grants and governance SELECT; User and governance are required, and any additional application schemas must be from the current quickstart. No writer global SELECT, PROCESS, TRIGGER, ALL, grant option, role or dynamic grant is accepted. The independent observer accepts schema-limited performance_schema SELECT plus global PROCESS; the known existing global SELECT/PROCESS and SELECT/TRIGGER/PROCESS profiles are also recognized, with TRIGGER unused. Global SELECT is not required for the new observer profile; actual visibility of its own owner attributes and required P_S tables must still succeed. Grant recipients are bound to actual CURRENT_USER. A global observer grant need not emit a separate USAGE row. Native writer privileges are never widened. Actual SQL grant compatibility remains UNRUN; unsupported forms refuse. No privileges are provisioned. Native authorization and the producer's existing nested transaction/savepoint ownership are preserved outside this explicitly owned lease.

`leaseGetFacts()`, `leaseCommit()`, `leaseRollback()` and finally `leaseAbort()` are the candidate API. Every caller must inspect cleanup evidence. No route, restoration provider or durable approval consumes the result. All thirteen required families remain, restoration remains blocked, and the new option is locked and false by default.

`session-lease-cases.php` is a callable isolated native SQL plan, not part of an accepted gate. It uses real native User creation, actor requests and the existing worker action which invokes actual SessionEngine session issuance. Both commit and rollback cases require an observed PRIMARY lock wait, unchanged protected capture, release, independently finished native INSERT and changed subsequent binding. These cases, the supported mapper, concurrency, permissions and physical fault matrix are UNRUN. The host controls execute the actual lease and AuthSession hook with explicit SQL, routing and parent DAO INSERT collaborators; they do not prove authentication, physical transactions or database lock waits. No existing normal or focused count is changed.

`governance_recovery_session_lease_owned_entry` connects only an already owned supplied metadata observer configuration, checks its live principal/role/proxy and exact owner attributes, then invokes the actual SQL cases. It does not call the RR principal preparation helper because that helper adds mysql.* privileges to the native writer. The caller must supply and later clean its already owned observer; this entry closes only the connection it constructs. It is a callable SQL entry, not a new CLI/CI gate or an execution receipt.

MySQL 8.4 documents that an ordinary authenticated account can read its own USER_ATTRIBUTES row without broader mysql.user privileges: https://dev.mysql.com/doc/refman/8.4/en/information-schema-user-attributes-table.html . The Performance Schema SELECT model is documented at https://dev.mysql.com/doc/refman/8.4/en/performance-schema-table-characteristics.html . These source references support the intended limited observer design; they do not replace actual isolated SQL permission and physical event tests.
