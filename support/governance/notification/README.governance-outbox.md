# Committed governance notices — isolated candidate

This source candidate adds a separate locked, default-false
`governance.notifications.enabled` option. The existing private-mail option does
not enable new governance producers. No deployment or activation has occurred.
The new pure and SQL obligations are not runtime acceptance until an exact
signed source has passed the supported isolated runner.

The initial audience is current eligible native system administrators. A Project
notice additionally requires the recipient's actual native Project VIEW. No
membership, appointment, policy, recovery permission or visibility is granted by
an event, binding, recipient mapping, queue receipt or email link.

## Transaction and delivery boundaries

The organization service's central audit insertion covers its native unit,
membership, administrator appointment, approval and handover adapters. Project
approval and recovery stop classification have separate native audit hooks.
Each hook reads its actual stored audit row and inserts a metadata-only event
and deterministic `metamta_gorgeoutbox` relay through the original physical
business connection. Qualified identifiers do not open a second MetaMTA
transaction. Same-primary routing, fixed libraries and actual InnoDB sources are
required. A missing, unknown or unsupported source refuses the operation.

Event metadata contains a schema version, fixed source kind/action, opaque audit
identifier, hashes of the exact operation and actor bindings, timestamp and fixed audience kind.
It contains no names, lists, audit snapshots, contact addresses, reasons, private
body, URLs, tokens or caller permission booleans. Unknown fields are rejected.
Recovery stop classification remains an attestation, never a recovery permit.

After commit, the notice worker locks the event and prepares one native mail
per eligible recipient. Event state, recipient mapping, native mail, MAIL
recipient edges and the existing native mail-delivery outbox must share one
MetaMTA transaction. Native DAO and edge connections are checked for exact
identity. A prepared event is idempotent; replay does not generate replacement
mail or rewrite an immutable snapshot. An audience exceeding 128 planned native
administrators refuses the entire event rather than silently truncating it.
Paging beyond that bounded profile remains an activation gate.

The existing private-mail path provides generic subject/text, no HTML,
attachments or original headers. Its current-policy callback invokes the new
notice policy at every physical attempt, including provider retry/fallback.
The policy checks actual event/audit consistency, the persisted mail mapping,
current native recipient eligibility, Project VIEW where applicable, and exactly
one verified primary email with the bound PHID/address. It never trusts the
queue's recipient assertion. Existing sticky quarantine prevents a denied mail
from reviving after role/email restoration.

Account binding uses the actual native noncredential identity facts: native USER eligibility-transition generation (disable, approval and administrator changes),
always-on legacy-role epoch and identity digest. Benign username edits do not
discard an otherwise deliverable notice. This
is not an actor or credential grant, and does not invoke recovery capture or
initialize a credential epoch. The native disable/enable regression keeps the
stop-ledger feature false and performs both real native transactions before any
callback. Direct unknown writers and database restore lineage are not certified
by this mechanism; restore/outbox replay requires the separate N13 gates.

## Isolated obligations

The candidate fixture covers real native audit hooks, source-bound metadata,
operation replay, real Gorge inbox deduplication/lease/finalize and the native
`worker.execute` handler. It separately checks private snapshots, current
recipient disablement, native disable/enable ABA, primary address changes,
unverified/duplicate primary rows, same-address replacement, metadata/audit
drift and Project VIEW revocation.

The producer fault is injected after both qualified outbox writes, at the
organization operation insertion. The worker fault is injected after native
mail/edge/outbox writes and before mapping insertion. Full row fingerprints and
closed transactions are required after rollback. A real independent PHP process
waits inside an owned INSERT trigger; actual lock-wait provenance and an
independent reader establish before/after commit visibility. The test also
refuses an actual MyISAM outbox. All fixture DDL, triggers, processes and private
files are owned and must be removed.

The queue profile manually relays the actual committed stored payload over real
loopback Gorge HTTP and invokes native Conduit in-process. It is not an
automatic Go relay/worker-daemon, HTTP gateway or SMTP proof. The upgraded
isolated mail stack and an actual per-physical-attempt callback matrix remain
required for this new producer; existing Wiki/business SMTP evidence is not
reused as new-notice evidence.

## Remaining complete-feature gates

The central hook is not runtime proof for every operation. Administrator grants
and revocations, each handover lifecycle action, organization approval phases,
Project approval/consume, recovery classification, rollback/retry/fallback and
each supported recipient projection need their own actual matrix. Team managers,
participants and ordinary subject notices require explicit current native
projection adapters; they are not silently included in the administrator
profile. In-app/feed/live notifications, specific recovery-history navigation,
trusted browser behavior, large-audience paging, operational cleanup/retention,
restore lineage, paired release and production activation remain unproved.

All four native authority axes and production defaults remain unchanged.
